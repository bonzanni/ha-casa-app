# An agent's lane

> Code is the source of truth. This file is a map; when it and the code disagree, the code wins.

## Scope

The one lane, queue and fault each executing agent has: who has a lane, what counts as a use
of it, how a place in its queue is reserved and released, the deadline a use may wait under,
and the fault that takes an agent out of service until Casa restarts. What a delegation does
when the lane refuses it is [`delegation.md`](delegation.md); the stored-call tap that runs
on the lane is [`stored-call-buttons.md`](stored-call-buttons.md), and how its pinned run is
terminated and what faults the agent is
[`stored-call-termination.md`](stored-call-termination.md); the configurator's lease, which a
configurator run takes after its lane, is [`configurator.md`](configurator.md).

## Mental model

**An agent's plugin work runs one use at a time.** A specialist and the configurator each
have a lane (`agent_lane.has_lane`); a resident has none. A stored-call tap, a plugin
continuation, a delegation to the agent and a run Casa carries on after an approval are each
one use of it. The lane is a lock with a short queue in front of it: a use reserves its place
before any task exists, waits until it is at the head of the queue, then takes the lock. The
place is released once, on admission or on any earlier exit, so a use reserved earlier is
never overtaken by one that reached the lane sooner. At most three uses wait; a fourth is
refused at once, and no task is created for it.

**The lane is the agent's, never a chat's.** The operator's private chat has the same id on
every bot, and one agent's plugin processes are one set whichever chat asked for them, so a
use from the resident's chat and a use from the agent's own chat wait in the same queue,
while another agent's lane is free meanwhile.

**A use can wait under a deadline.** With one, the wait ends there: the place is released and
the use holds nothing. A configurator use waits under the same `LEASE_WAIT_S` deadline its
lease wait would, so past it the refusal is the configurator's typed busy result
(`ConfiguratorBusy` is a `LaneBusy`).

**A fault is the agent's until restart.** An agent whose pinned run could not be confirmed
terminated is faulted: every later use of its lane is refused at once, and the standing
health report lists it against the plugin that run ran. Nothing persists the fault, so a
restart is what clears it. A run still unwinding past its runner's teardown bound refuses the
lane the same way, but only until it has ended, and it is not a fault: no health row.

## Contracts & invariants

**INV-DESK-006**: Each executing agent has one lane and one fault, keyed by the agent alone: every use of it — a stored-call tap, a continuation, a delegation from any chat or bot — waits in one queue of at most three behind one lock, and a faulted agent refuses every use at once until Casa restarts.

A run still unwinding past its runner's teardown bound refuses the lane only until it ends,
and is not a fault. A delegation to a faulted agent is the typed `agent_faulted` result,
before any queue place ([`delegation.md`](delegation.md)).

## Failure behavior

**A full queue.** The use is refused at once; no task is created and no place is held.

**A use cancelled while it waits, or a task cancelled before its coroutine started.** Its
place is released by the holder's done-callback, and the next use in line goes through.

**Casa restarts.** The lanes and the faults are gone; the agent is in service again.

## Extension points

**A new kind of use** reserves a place before it creates its task and enters through
`Lane.use`, so it waits in the same queue and inherits the fault check.
